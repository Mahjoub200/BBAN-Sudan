# BBAN Sudan V2 — قاعدة بيانات ولوحة تحكم

هذه الحزمة تضيف مزامنة قائمة البنوك من Supabase، ولوحة إدارة محمية بتسجيل دخول، وعدادات استخدام مجمعة. واجهة الموقع تعمل محلياً حتى قبل إعداد قاعدة البيانات، باستخدام قائمة البنوك المضمّنة.

## ما الذي تحفظه قاعدة البيانات؟
- بيانات البنك: الاسم بالعربية والإنجليزية، البادئة واللاحقة، حالة توثيق الصيغة، التفعيل، ترتيب العرض، ورابط الشعار.
- أحداث مجمعة: اختيار بنك أو محاولة إنشاء BBAN، مع معرّف البنك ومسار الصفحة.
- **لا يتم إرسال رقم الحساب أو رقم BBAN أو البريد أو اسم المستخدم أو كلمة المرور إلى قاعدة البيانات.** لا تضف هذه الحقول إلى سجلات التحليلات.

## 1) إنشاء مشروع Supabase
1. أنشئ مشروعاً في https://supabase.com (الخطة المجانية تكفي للبدء، وتخضع للحدود الحالية للخدمة).
2. من Project Settings > API انسخ Project URL و anon/public key.
3. افتح SQL Editor، والصق كامل `supabase/schema.sql` ثم Run.
4. من Authentication > Users أنشئ مستخدم المشرف ببريدك وكلمة مرور قوية.
5. انسخ UUID الخاص بالمستخدم، ثم شغّل هذا الاستعلام بعد استبدال UUID:

```sql
insert into public.admin_users(user_id)
values ('ضع-UUID-المشرف-هنا')
on conflict do nothing;
```

## 2) إعداد الموقع
افتح `config.js` واستبدل القيم:

```js
window.BBAN_CONFIG = {
  SUPABASE_URL: "https://YOUR-PROJECT.supabase.co",
  SUPABASE_ANON_KEY: "YOUR_SUPABASE_ANON_KEY",
  ENABLE_CLOUD: true
};
```

استخدم anon/public key فقط. **ممنوع وضع service_role key في ملفات الموقع أو GitHub.**

## 3) النشر على GitHub Pages
انسخ محتويات هذا المجلد إلى جذر مستودع `BBAN-Sudan` (بما فيها الملفات المخفية)، ثم من Termux:

```bash
git add -A
git commit -m "BBAN Sudan V2: Supabase cloud and admin dashboard"
git push origin main
```

إعداد Pages الحالي: Deploy from a branch > `main` > `/(root)`.

## 4) لوحة الإدارة
بعد النشر افتح:

`https://mahjoub200.github.io/BBAN-Sudan/admin.html`

سجّل الدخول بحساب المشرف الذي أنشأته في Supabase. يمكنك إضافة/تعديل/حذف البنوك ورفع الشعارات حتى 2MB، وتغيير حالة الصيغة. لا تصف الصيغة بأنها موثقة إلا بعد الرجوع إلى مستند رسمي.

## 5) اختبار التشغيل
- افتح الصفحة الرئيسية؛ إذا تعذّر الاتصال بـ Supabase يستمر الموقع باستخدام القائمة المحلية.
- بعد تفعيل الاتصال، يجب أن تظهر قائمة البنوك من جدول `banks`.
- جرّب إضافة بنك تجريبي من لوحة الإدارة ثم حدّث الصفحة الرئيسية.
- راجع إحصائيات الاستخدام من لوحة الإدارة.

## ملاحظات مهمة
- ملفات `index.html` و`admin.html` و`config.js` عامة لأنها منشورة على GitHub Pages. المفتاح المسموح وضعه هنا هو anon/public فقط، والحماية الفعلية تعتمد على سياسات RLS في `schema.sql`.
- لا توجد قاعدة بيانات متصلة فعلياً حتى تنشئ مشروع Supabase وتضع بياناته في `config.js`.
- الصيغ الحالية موروثة من القائمة المحلية وتُدرج في قاعدة البيانات بحالة `unk` (غير مؤكدة)، ومحفظة Cashi معطلة افتراضياً. لا يثبت نجاح حساب BBAN وجود الحساب أو صحة الصيغة المصرفية.
- GitHub Pages لا يشغّل خادماً خلفياً؛ Supabase هو خدمة الخلفية السحابية.

## إعداد Supabase لهذا المشروع
تم تجهيز `config.js` برابط المشروع ومفتاح Publishable الذي زوّدنا به صاحب المشروع، وتم تفعيل الاتصال السحابي. المفتاح Publishable مخصص للاستخدام في المتصفح؛ لا تضع مطلقاً `service_role` أو Secret Key في ملفات الموقع.

بعد رفع الملفات إلى GitHub Pages، افتح الموقع وتحقق من تحميل قائمة البنوك. إذا ظهرت رسالة `Invalid API key` في وحدة التحكم، فهذا يعني أن المفتاح المنسوخ لا يطابق مفتاح المشروع الحالي؛ استبدله من Supabase > Connect > Publishable Key. كما يجب أن تكون سياسات RLS في `supabase/schema.sql` قد نُفذت بنجاح.
